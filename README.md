# Topology-Aware Road Extraction from Sentinel-2 Imagery

Code developed for the Master's thesis:

**Topology-Aware Road Extraction from Sentinel-2 Imagery: U-Net Architectures on the Amazon Wild Roads Dataset**

**Supervisors:** Prof. Ludovico Giorgio Aldo Biagi, Nikolina Zallemi

This project investigates whether topology-aware auxiliary supervision can improve road extraction from Sentinel-2 imagery and influence the structural organization of predicted road networks.

A standard U-Net for binary road segmentation (**UNetSingle**) is compared with a topology-aware multi-head U-Net (**UNetMultiHead**) trained with auxiliary centerline and junction supervision. The final output used for comparison is always the binary road mask.

## Models and Experiments

UNetMultiHead is trained with five loss-weight configurations:

| Configuration | Mask | Centerline | Junction |
|---|---:|---:|---:|
| `equal` | 1.0 | 1.0 | 1.0 |
| `aux05` | 1.0 | 0.5 | 0.5 |
| `aux025` | 1.0 | 0.25 | 0.25 |
| `center_focus` | 1.0 | 1.0 | 0.25 |
| `junction_focus` | 1.0 | 0.25 | 1.0 |

All final experiments use the random seeds:

```text
42
123
2025
```

## 1. Generate Topology Labels

Run:

```bash
python make_topology_labels_phase1.py
```

Before running the script, set the correct `DATA_DIR`.

This creates:

```text
centerline_phase1/
junction_phase1/
```

inside the dataset directory.

Centerlines are generated by skeletonizing the road masks. Junctions are derived from skeleton pixels with at least three neighbors in an 8-connected neighborhood and are dilated with a `3 × 3` structuring element.

These topology labels are used only as auxiliary supervision during training. The final model comparison is performed using the predicted binary road mask.

## 2. Dataset Splitting and Patch Extraction

`dataset_awr_seg_mosaic_split.py` handles data loading and patch extraction automatically and does not need to be executed directly.

The final experiments use:

- patch size: `128 × 128`
- stride: `64`
- 20 development mosaics
- 8 fixed test mosaics
- 18 training mosaics and 2 validation mosaics per seed
- ImageNet normalization

The train/validation split is performed at the mosaic level before patch extraction. The test set remains fixed across all experiments.

## 3. Train UNetSingle

Edit the configuration section in:

```text
train_unet_single.py
```

Set:

- `DATA_DIR`
- `SEED` to `42`, `123`, or `2025`
- the corresponding `OUTPUT_DIR`

Then run:

```bash
python train_unet_single.py
```

Training uses:

- 20 epochs
- batch size: 8
- Adam optimizer
- learning rate: `1e-4`
- `BCEWithLogitsLoss`
- checkpoint selection based on validation Dice

Repeat the experiment for all three seeds.

## 4. Train UNetMultiHead

Edit:

```text
train_unet_multihead.py
```

Set:

- `DATA_DIR`
- `SEED`
- `EXPERIMENT_NAME`
- `W_MASK`
- `W_CENTERLINE`
- `W_JUNCTION`

Activate one loss configuration at a time using the weights shown in the table above.

Run:

```bash
python train_unet_multihead.py
```

Repeat for all five loss configurations and for seeds `42`, `123`, and `2025`.

The best checkpoint is selected according to validation Dice of the road-mask head.

## 5. Final Pixel-Wise Evaluation

Run:

```bash
python evaluate_models.py
```

Before running, set the correct `DATA_DIR` and verify that the checkpoint paths match the folders produced during training.

For the final thesis comparison, use the **mask metrics** produced by this script:

- Precision
- Recall
- Dice / F1
- IoU

These metrics are computed globally over the fixed test set.

The script also contains additional skeleton/head and legacy connectivity outputs from earlier experimental stages. These are retained as part of the experimental code but are not used in the final reported thesis comparison.

## 6. Final Connectivity Evaluation

Run:

```bash
python evaluate_connectivity_corrected_lcc_only.py
```

Set the correct `DATA_DIR` and verify the checkpoint paths before running.

The final connectivity analysis uses:

- mean number of connected components
- Corrected LCC ratio

Corrected LCC is defined per patch as:

```text
largest connected component of (prediction AND ground truth)
-------------------------------------------------------------
              total predicted foreground pixels
```

Connectivity is evaluated using 8-connectivity and averaged over the test patches. Final results are aggregated across the three seeds.

## 7. Qualitative Visualizations

The following scripts are optional and reproduce the qualitative analyses used during the project:

```text
generate_qualitative_candidates_with_aux05.py
generate_connectivity_fragmentation_candidates_with_aux05.py
generate_full_mosaic_visuals_with_aux05.py
```

They require trained checkpoints and the correct `DATA_DIR`.

These scripts are intended for qualitative interpretation only. The quantitative thesis results are obtained from the evaluation scripts described above.

## Reproduction Order

```text
1. Download the Amazon Wild Roads dataset
2. Set DATA_DIR in the relevant scripts
3. Generate centerline and junction labels
4. Train UNetSingle for seeds 42, 123, and 2025
5. Train all UNetMultiHead configurations for the same three seeds
6. Run evaluate_models.py for final pixel-wise metrics
7. Run evaluate_connectivity_corrected_lcc_only.py for final connectivity metrics
8. Optionally generate qualitative visualizations
```
